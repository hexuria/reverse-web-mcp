The Benchmark Bench

The target app, the six arms, the thirteen tasks, and what a result file actually holds.

01 · the target

One app, five doors, one oracle

Customers, invoices, an outbox, payments. The same handler set behind every door, so no arm gets a different app — only a different way in.

doorpathwho uses it

Approve is deliberately UI-only. There is no API for it, and the server refuses the call without the page's header. Every arm has to prove it can mix one screen node into an otherwise-API plan, or fail the task.

The oracle counts effects independently

Every arm records through one Recorder. A ledger row means the same thing whether rwmcp, a script, or a model loop produced it, and write-ness comes from the world model rather than an arm's own say-so. That is what makes the comparison a measurement instead of a claim.

04 · one result file

What a run leaves behind

One JSON per task × arm × run, plus a config.json recording the exact options used — the API key never among them.

  • status, model samples, tokens, wall time
  • max parallel — a sweep over the ledger's microsecond spans, and the decisive column
  • the same sweep per surface, so a screen lane should read 1 while the API stays wide
  • correctness against the task's expected end state, read from the oracle
  • double-sends, from the app's outbox
  • forks taken, the full ledger, the oracle snapshot, and for rwmcp the rendered plan
bench verify recomputes the headline numbers from the raw rows and fails if anything stored disagrees. A result that cannot be recomputed is not evidence.
05 · running it safely

Nothing touches your screen

Every screen arm drives a headless Chromium over CDP, on the host or in the container, so no run anywhere reaches your screen, mouse or keyboard. The click loop saves the screenshot it acted on each turn, which is the recording.

bench run resets the target app before every single run and installs chaos. It is a benchmark harness. Never point it at anything you care about — see the setup guide for the two safe ways to run real work.
